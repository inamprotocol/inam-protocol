# Use of the INAM name

The code and specification are Apache-2.0, and that license doesn't grant rights to the project's name (Apache-2.0 §6). This file says how the name may be used, so forks and integrations stay clear about which registry is which.

**Fine without asking:**

- Saying your software "implements the INAM Protocol", is "compatible with INAM", or "uses INAM reputation".
- Naming a package or integration after what it connects, e.g. `langchain-inam` or `inam-verifier-foo`, as long as its README says it isn't an official project.
- Referring to INAM in articles, talks, comparisons, and research.

**Needs permission (ask at legal@inamprotocol.org):**

- Calling a fork, a modified specification, or a hosted registry "INAM" or "INAM Protocol", or anything else that suggests it's the official one.
- Using the name in a company or product name, or a domain name.
- Implying endorsement, certification, or partnership.

A registry that runs this code under another name is welcome. What matters is that a caller can tell which operator's reputation data they're reading.
