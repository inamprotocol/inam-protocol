# Contributing

INAM Protocol is a reference implementation of an open protocol
(Apache-2.0, pre-1.0). This file covers local setup and how the test
suites are organized. For protocol semantics — what an endpoint means,
what a field is for, why a design choice was made — read
[`SPEC.md`](./SPEC.md) first, not this file.

## Before proposing a change

Read the **"Deliberate simplifications — and the upgrade path for
each"** section of [`README.md`](./README.md#deliberate-simplifications--and-the-upgrade-path-for-each).
A number of things that look like missing features (in-memory storage,
no multi-verifier consensus, no stake-posting endpoint, etc.) are
intentional scope decisions with a documented upgrade path, not gaps
waiting to be filled. If you're planning a change in one of those areas,
open an issue first to check it's actually in scope before writing code.

## Local setup

There are three independently-runnable pieces: the root Node reference
server, the Cloudflare Worker implementation, and the Python SDK. Each
has its own dependencies.

### Root Node server (`src/`) + TypeScript SDK (`sdk-js/`)

Root tests (and the dev server) import `sdk-js/src` directly (see
`tsconfig.json`), and `sdk-js` is its own nested package with its own
`package.json` — so both need `npm install`, or `npm run dev` fails with
`ERR_MODULE_NOT_FOUND` for `sdk-js`'s dependencies (e.g. `@noble/curves`):

```
npm install
cd sdk-js && npm install && cd ..
```

Then:

```
npm run dev     # run the reference server locally (tsx watch)
npm test        # run the vitest suite (tests/*.test.ts)
```

### Cloudflare Worker (`worker/`)

```
cd worker
npm install
npm test         # vitest via @cloudflare/vitest-plugin, runs against wrangler.jsonc
npm run typecheck
```

No extra setup (no manual `wrangler types` step) is needed before
`npm test` — the vitest plugin reads `worker/wrangler.jsonc` directly.

### Python SDK (`sdk-python/`)

The repo doesn't commit a venv; create your own local one (it's
gitignored, e.g. `sdk-python/.venv/`):

```
cd sdk-python
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -e . pytest   # Windows
# ./.venv/bin/python -m pip install -e . pytest          # macOS/Linux
./.venv/Scripts/python.exe -m pytest -v
```

`tests/test_interop.py` and `tests/test_verification_interop.py` check
this SDK's output against fixed cross-language vectors generated by the
TypeScript reference implementation — if you change canonical JSON,
`did:key` encoding, or signing in either language, expect these to catch
a mismatch.

## How the tests are organized

| Suite | Location | Runner | Count (last known-green run) |
|---|---|---|---|
| Reference server | `tests/*.test.ts` | vitest (root) | 38 |
| Worker | `worker/tests/*.test.ts` | vitest + `@cloudflare/vitest-plugin` | 31 |
| Python SDK | `sdk-python/tests/*.py` | pytest | 23 |

All three exercise the same protocol semantics from different runtimes;
a change to shared logic (canonical JSON, receipt content IDs, signing)
should be reflected — and tested — in all three, not just one.

## CI

`.github/workflows/ci.yml` runs the root Node suite, the Worker suite,
the Python suite, and a TypeScript typecheck (root + worker) as separate
jobs on every push and pull request to `main`, so a failure is
attributable to a specific runtime. A PR should have all four green
before merge.

## Commit / PR expectations

- Keep changes scoped — this repo has three runtimes plus two SDKs that
  need to stay in agreement; don't change shared semantics in only one
  place.
- Run the relevant test suite(s) locally before opening a PR.
- If you touch `SPEC.md`, explain the "why" in the PR description —
  spec changes affect every implementation and SDK, not just this repo.
